# 2026.261.0620 — feat: build the shared host for armv7

## Summary of changes

Adds **`armv7`** to the `charly-lib` shared multi-call plugin host build and release.

- `.github/workflows/build.yml`: the build loop grows from `amd64 arm64` to `amd64 arm64 armv7`, with a per-arch `goenv` mapping (`armv7` → `GOARCH=arm GOARM=7`; every other suffix its own `GOARCH`). `charly-lib-linux-armv7` joins the release assets. A new **arch-verification step** asserts each built host's ELF header (`file -b`) — the cross binaries cannot execute on the amd64 runner, so this is the gate that fails if an arch is dropped or built for the wrong ABI.
- `README.md`: the design line and the release-asset table gain `armv7`, with the `GOARCH=arm GOARM=7` note.

**Why armv7:** it is the 32-bit appliance target this release axis exists for — a JetKVM's uClibc `armv7l` userland, and older 32-bit SBCs. It is the **same third architecture** `opencharly/charly` already publishes for the `charly` binary and the per-plugin `charly-plugins-linux-armv7.tar.gz`. Without it the shared host cannot serve an appliance once that appliance's packaging migrates off per-plugin binaries — `packagekit` now **HARD-ERRORS** on the retired per-plugin layout (opencharly/charly-alpine#1, charly-debian#3, charly-fedora#3, charly-openwrt#1, charly-ubuntu#4).

**Closes / relates to:** the armv7 gap surfaced while adding the appliance installer (`opencharly/charly-jetkvm`); the per-plugin layout still ships for armv7 today, so this is the shared-host path catching up, not yet a hard requirement.

**Breaking change + rollback:** `none` — a new build target and a new release asset; no existing asset changes shape. Revert the merge to roll back.

**Why the release-asset line needs no separate dispatch:** the workflow's `Publish the release` step is guarded by `if: inputs.version != ''`. The dispatch above intentionally omitted `version` (build-only), so it exercised every changed line **except** the tag/publish — and the changed `files:` entry `bin/charly-lib-linux-armv7` names a path the verification step above already asserts exists with the right architecture. Dispatching a second time WITH a `version` would mint a real release tag from a PR branch, which is not done; the publish path is the same `softprops/action-gh-release` step that already ships amd64+arm64 on `main`.
